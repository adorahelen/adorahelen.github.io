> **참여**: SK쉴더스 EQST Lab, 중앙대 산업보안학과 TrustworthyAI Lab(김호기)
> **핵심 한 줄**: 레드티밍 가이드가 "어떻게 점검하나(How to test)"라면, 이 매뉴얼은 "무엇이 위협이고 어떻게 진단·완화하나(What & How to fix)"다.

이 글은 (1) 매뉴얼 본문 정리, (2) 매뉴얼 참고문헌 100여 건을 클러스터로 묶어 심화 조사한 내용(국제표준 / 프론티어 거버넌스 / 한국 규제 / 정렬기법 계보 / 공격논문↔위협코드 매핑), (3) 조사 중 확인된 **매뉴얼 자체의 보정 2건**으로 구성한다.

## 0. 두 문서의 관계 — 왜 함께 봐야 하는가

레드티밍 가이드(2026-02)의 위협 분류표에 *"구체적인 분류 기준은 'AI 보안 위협 대응 매뉴얼'을 참고"*라는 문장이 있다. 그 매뉴얼이 이 문서다. 둘은 KISA AI 보안 레드팀의 **매칭 세트**다.

| | 레드티밍 가이드 (2026-02) | 위협 대응 매뉴얼 (2026-01) |
|---|---|---|
| 역할 | 레드팀 **운영 프로세스** (구성→준비→이행→보고) | 위협 **카탈로그 + 진단 + 완화** |
| 독자 | 레드팀 실무자·PM | 보안팀·CISO·SOC·개발자·도메인 담당자 |
| 위협 코드 | D01~03 / M01~08 / A01~04 / S01~04 (동일) | **동일 + H01/H02 추가** |
| 산출물 | 시나리오·보고서 템플릿 | 산업별 32개 시나리오 + 진단 코드 + 대응표 |

가이드는 위협 코드를 "점검 대상"으로 나열만 하지만, 매뉴얼은 각 코드에 **정의·발생원인·영향·평가기준(양호/취약)·진단방법(실제 코드)·대응방안·실제 사례**를 붙인 별첨2(59페이지)를 제공한다. 실무 진단은 이쪽이 원전이다.

## 1. 개념 골격 — 가이드에 없던 상위 프레이밍

### AI 안전 vs AI 보안 (출처: MIT AI Risk Repository)

| | AI 안전(Safety) | AI 보안(Security) |
|---|---|---|
| 발생요인 | AI 자체 결함·인간 활용 방식 | 악의적 행위자 |
| 보호대상 | 시스템 **외부**(사용자·사회·환경) | 시스템 **내부**(모델·데이터·인프라) |
| 의도성 | 비의도적 | 대부분 의도적 |

### 내재적 vs 외재적 위협 (출처: 중앙대 TrustworthyAI Lab)

- **내재적(Intrinsic)**: 외부 공격자 없이도 LLM 자체에서 발생 — 학습데이터 편향, 환각, **정렬 실패**, **확률적 비결정성**
- **외재적(Extrinsic)**: 공급망·도구·인프라·외부데이터·사용자 경계 + LLM을 도구로 쓰는 외부 행위자 — 탈옥, 모델 추출, 공급망 공격, 고성능 모델 위협

> 국제 AI 안전보고서 2026(Bengio 외)의 3분류(악의적 사용/기능 장애/시스템적 위험)와 정합. 내재적≈기능 장애, 외재적≈악의적 사용+시스템적.

### LLM 시스템 6대 구성요소 (KISA 각색, 원전: Databricks DASF 2.0)

단독 모델이 아니라 **LLM 시스템**이 분석 단위 — 2025 하반기 에이전트화 + 2026 상반기 MCP 생태계 급팽창이 배경.
① 모델 공급망 ② 에이전트 도구(MCP·플러그인) ③ 운영 인프라(추론엔진·GPU) ④ 외부 데이터(벡터DB·RAG) ⑤ 사용자·운영자 경계(신원) ⑥ 고성능 모델(시스템 외부)

> ⚠️ **보정**: 매뉴얼은 이 6-요소 모델을 Databricks DASF 2.0에 귀속하나, **DASF 2.0 원문은 12-컴포넌트·4-스테이지(62위험→64통제) 모델**이다. 매뉴얼의 6-요소는 KISA가 재구성한 축약본으로 이해해야 한다.

## 2. 위협 분류 — 가이드와 동일 + H축 추가

**D/M/A/S 코드는 가이드와 완전히 동일.** (D01 불균형 / D02 부정확 / D03 개인정보 비식별화 미흡 / M01 학습데이터 유출 / M02 벡터DB·임베딩 유출 / M03 시스템프롬프트 유출 / M04 모델 유출 / M05 환각 / M06 탈옥 / M07 부적절 출력처리 / M08 모델 DoS / A01 부적절 도구설계 / A02 하이재킹 / A03 에이전트 DoS / A04 메모리 오염 / S01 데이터 포이즈닝 / S02 모델 포이즈닝 / S03 취약 추론엔진 / S04 취약 확장요소)

### 고성능 모델 위협 (H) — 이 문서의 핵심 추가

- **H01 고도화된 사이버 공격 지원**: 고성능 모델이 악성코드 작성·해킹 자동화에 악용 → 비전문 공격자 역량 상향. (근거: MITRE ATLAS AML.T0048)
- **H02 자율성으로 인한 통제 상실**: 에이전트 자율 판단이 통제 범위 이탈. (근거: OWASP LLM06 Excessive Agency)

> 운영자가 직접 통제하는 대상이 아니라 **위협 모델 설계 시 공격자의 가용 능력 상한**으로 상정해야 하는 차원. → 아래 §3-② 법적 근거, §4-③ 프론티어 통제배포와 직접 연결.

## 3. 참고문헌 심화 ① — 프레임워크·거버넌스 (전량 웹 검증)

매뉴얼의 위협은 세 층위 문헌에 뿌리를 둔다: **국제 표준 → 규제·정부평가 → 프론티어 랩 통제배포**.

### ① 국제 표준·위험분류

| 문헌 | 무엇 | 매뉴얼에서 정당화하는 것 |
|---|---|---|
| **국제 AI 안전보고서 2026** (Bengio 외, arXiv 2602.21012) | 30개국+·100명+ 참여 2차 보고서, **악의적 사용/오작동/시스템적** 3분류 | 위협 taxonomy 상위 틀 |
| **NIST AI RMF 1.0**(AI 100-1) + **GenAI Profile**(AI 600-1) | Govern·Map·Measure·Manage 4기능 + 생성형 특화 12위험 | 위험 거버넌스 골격 |
| **NIST AI 100-2 e2025**(Vassilev) | 적대적 ML 공격·완화 분류, **NISTAML.xxx 코드** | 공격 유형 표준 코드 |
| **MITRE ATLAS** | AI 대상 14전술·80+기법, **AML.Txxxx 코드** | 별첨1 매핑 근거 |
| **EU GPAI Code of Practice**(2025.7) | AI Act GPAI 의무(투명성·저작권·안전보안) 자발적 규약 | 범용AI 규제 준수 |

### ② 규제·정부평가

- **NIST IR 8596 Cyber AI Profile**(2025.12 예비초안): CSF 6기능에 정렬, 3초점 = AI 시스템 보안 / AI 활용 방어 / **AI 기반 공격 저지**. → 매뉴얼 H01의 CSF 접목판.
- **CAISI**(NIST 산하): 정부-랩 **자발적 프론티어 AI 사전평가 협정**(Anthropic·OpenAI·Google·MS·xAI), 40건+ 수행. → "정부가 프론티어 모델을 공개 전·후 평가"하는 통제 모델.

### ③ 산업 보안 프레임워크

- **Databricks DASF 2.0**: 12-컴포넌트/4-스테이지, 62위험→64통제. (매뉴얼 6-요소의 원전)
- **Google SAIF / SAIF 2.0 Secure Agents**: 에이전트를 4구성요소로 분해, 자율성·도구권한·메모리오염·멀티에이전트 위험. → 매뉴얼 A01~A04·H02 통제 매핑의 국제 대응물.

### ④ 프론티어 랩 통제배포 — H축의 실증

매뉴얼이 H01 대응방안("단계적 배포·검증된 사용자 한정")의 근거로 든 실제 사례:
- **OpenAI GPT-5.5-Cyber + Trusted Access for Cyber(TAC)**: 이중용도 사이버 역량(레드팀·취약점 검증·바이너리 분석)을 신원·신뢰 검증된 방어자에게만 제한 배포.
- **Anthropic Claude Mythos Preview / Project Glasswing**: 최강 코딩·에이전트 모델을 **오용 방어책 미확립으로 미공개** 유지하고, 중요 SW 방어 목적(주요 OS·브라우저 zero-day 수천 건 식별)으로만 제한 활용. (AWS·Apple·Google·MS·NVIDIA 등 참여)
- **CSA/OX Security "MCP by Design"**(2026.4): MCP SDK의 STDIO 설계상 systemic RCE 폭로(1.5억 다운로드·7천+ 서버 영향, 10+ Critical CVE). → 매뉴얼 **S04(취약 확장요소)·에이전트 도구 생태계** 위협의 근거.

> **종합**: 위험분류(Intl AI Safety Report) → 표준 코드(NISTAML/ATLAS) → 규제·정부평가(EU GPAI·CAISI·IR 8596) → 프론티어 통제배포(GPT-5.5-Cyber·Mythos)로 이어지는 **"2026 프론티어 거버넌스 레이어"**. 앞 글(레드티밍 가이드)에서 정리한 Microsoft·Anthropic·OpenAI 레드팀 교훈이 이 매뉴얼에선 **법·표준·배포정책 층위**로 올라와 있다.

## 3-보론. 한국 규제 스택 — 32개 산업 시나리오의 법적 근거

### 법·의무 (⚠️ 중요 보정 포함)

- **인공지능기본법**(2026.1.22 시행) **제2조제4호 고영향 AI**: 생명·신체·기본권 중대 영향 **10개 영역** — 에너지·먹는물·보건의료·의료기기·원자력·범죄수사·채용/대출심사·교통·공공서비스·교육. → 매뉴얼 32개 산업 시나리오가 이 10영역에 매핑됨.
- ⚠️ **보정**: 매뉴얼 참고문헌은 *"고영향 AI(제2조)·안전성 확보 의무(제32조)"*를 한 줄로 묶었으나, **제32조 안전성 확보 의무의 적용대상은 고영향 AI가 아니라 '고성능(프론티어) AI = 누적 연산량 10²⁶ FLOP 이상'**(임계값은 시행령에서 규정)이다. 법적 트리거가 다른 두 조항을 분리해야 한다.
- ✅ **오히려 이 보정이 매뉴얼 구조를 더 잘 설명한다**: 제2조(고영향 10영역) = **산업별 시나리오(§3)의 근거**, 제32조(프론티어 안전성 의무) = **고성능 모델 위협 H01/H02(§2)의 국내 법적 근거**. H축이 왜 별도로 존재하는지가 법으로 설명된다.
- **과기정통부 고영향 판단 가이드라인**(2026.1): 활용 영역 × 영향 수준으로 판단, 대상 = 위 10영역.
- **과기정통부 AI 보안 안내서**(2025.12): 기밀성·무결성·가용성 기반 생애주기 **113개 항목**. (이 매뉴얼의 상위 안내서)

### 개인정보위 프라이버시 스택

공개된 개인정보 처리 안내서(2024.7) · 합성데이터 안내서(2024.12) · AI 프라이버시 리스크 관리 모델(2024.12) · 생성형 AI 개인정보 처리 안내서(2025.8) · 국민생활 밀접 10대 분야(2025.3). → 매뉴얼 D03(개인정보 비식별화)·M01(학습데이터 유출) 대응방안의 준거.

> ℹ️ 참고: 매뉴얼이 인용한 "인공지능 프라이버시 안내서(2025.8)"는 별도 문서로 확인되지 않으며, 2025.8 "생성형 AI 개인정보 처리 안내서"의 별칭일 가능성. "국민생활 밀접 10대 중점분야"는 독립 안내서보다 정책추진계획 문서 형태로 확인됨.

## 4. 참고문헌 심화 ② — 정렬기법 계보 (매뉴얼 표 뒷받침)

매뉴얼은 정렬을 "단일 해결책이 아니라 입력필터+출력검증과 결합된 다층 방어의 일부"로 규정한다. 그 표의 각 기법 원전:

| 기법 | 대표논문 | 한 줄 기여 | 한계 |
|---|---|---|---|
| RLHF | Bai 2022 (arXiv 2204.05862) | 인간 선호→보상모델→RL로 helpful·harmless 정렬 | 라벨 비용·불안정 RL·과잉거부 |
| Constitutional AI/RLAIF | Bai 2022 (2212.08073) / Lee 2023 (2309.00267) | 원칙 기반 자기비판 + AI 피드백으로 인간라벨 축소 | 원칙 품질·AI 오류 전파 |
| DPO | Rafailov 2023 (2305.18290) | 보상모델·RL 없이 선호쌍 직접 최적화 | 오프라인 데이터 의존·분포이탈 |
| RBR | Mu 2024 (2411.01111, OpenAI) | 세분 규칙+LLM grader를 보상으로, 과잉거부 정밀조절 | 규칙 작성·유지 부담 |
| Deliberative Alignment | Guan 2024 (2412.16339, OpenAI) | 안전사양 학습 후 CoT로 사양 recall·추론 | 추론비용↑, 사양 품질 의존 |
| Machine Unlearning | Bourtoule 2021(SISA)/Golatkar 2020 | 특정 데이터 영향만 선택적 제거("잊기") | 완전삭제 검증 난제 |

> 어느 단일 기법도 완전한 안전을 보장하지 못하고 보상학습/규칙/추론/사후삭제의 상호보완적 결함을 가진다 → 매뉴얼의 "다층 방어" 주장을 기술적으로 뒷받침. 앞 글의 **"정렬만으로 방어 불충분(GCG)"**과 동일 결론.

## 5. 참고문헌 심화 ③ — 공격논문 ↔ 위협코드 ↔ 프레임워크 (별첨1)

매뉴얼 별첨1은 각 위협코드를 **OWASP ↔ NISTAML ↔ ATLAS ↔ 학술논문**으로 4중 매핑한다. 앞 글에서 조사한 공격 연구들이 여기 정확히 연결된다.

## 6. 핵심 교훈

1. **두 문서는 세트로 써야 완성** — 매뉴얼(위협 카탈로그+진단코드) + 가이드(레드팀 운영). 진단 원전은 매뉴얼 별첨2.
2. **H축은 법으로도 설명된다** — 기본법 제2조(고영향 10영역)=산업 시나리오, 제32조(프론티어 10²⁶ FLOP 안전성 의무)=H01/H02. 매뉴얼 참고문헌의 조문 병기(제2조·제32조)는 적용대상이 다른 두 트리거를 혼동시키지만, 분리하면 오히려 문서 구조가 정확히 설명된다.
3. **프론티어 통제배포가 2026 새 규범** — GPT-5.5-Cyber TAC·Anthropic Mythos/Glasswing = "이중용도 사이버 역량을 검증된 방어자에게만." 매뉴얼 32개 산업 시나리오 전부의 종착점(취약점 자율발굴→무기화 수시간)이 이 위협의 산업 파급판이며, 앞 글의 자동공격 연구(GCG→Subspace Rerouting)가 SCADA·펌웨어·OpenSSL로 확산된 형태.
4. **정렬은 다층 방어의 일부** — RLHF~Unlearning 6기법 어느 것도 단독 해결책 아님(앞 글와 동일 결론).
5. **참고문헌 그래프가 하나로 연결** — 두 KISA 문서가 공유하는 공격논문(Zou·Carlini·Greshake·Shumailov)이 OWASP/NISTAML/ATLAS 코드로 삼각 매핑됨. 국내 유일하게 Carlini 2024b(production LM 탈취)를 실무 체크리스트(logit-bias/logprobs 판별)로 번역한 자료.

## 부록: 조사 중 확인된 매뉴얼 보정 3건

1. **제32조 ≠ 고영향 AI** — 제32조 안전성 확보 의무는 고성능(프론티어, ≥10²⁶ FLOP) AI에 적용. 제2조 고영향(10영역)과 법적 트리거가 다름. (참고문헌 병기 시 분리 권장)
2. **DASF 2.0 = 12-컴포넌트** — 매뉴얼의 6-요소 LLM 시스템 모델은 KISA 각색. DASF 원문은 12-컴포넌트/4-스테이지.
3. **개인정보위 문서 명칭** — "인공지능 프라이버시 안내서(2025.8)"는 독립 문서 미확인(생성형 AI 안내서의 별칭 추정), "국민생활 밀접 10대 중점분야"는 정책계획 문서 형태.
