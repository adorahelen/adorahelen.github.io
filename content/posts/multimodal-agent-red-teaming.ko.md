> **맥락**: [가이드](/ko/posts/kisa-ai-redteaming-guide/)·[매뉴얼](/ko/posts/kisa-ai-threat-response-manual/)이 주로 텍스트 LLM을 표적으로 다뤘다면, 이 글은 그 경계를 넘어선 **멀티모달(이미지·음성) + 에이전트(툴사용·자율)** 공격 표면을 정리한다. 실무 층은 [AI 레드티밍 실무](/ko/posts/ai-red-teaming-practice/).
> **성격**: 연구·개념 수준 정리(익스플로잇 코드·공격 플레이북 아님). 방어자·SIEM 관점.
> **핵심 한 줄**: 근본 원인은 하나다 — **신뢰할 수 없는 입력(이미지 픽셀·외부 문서·도구 설명)을 "데이터"가 아니라 "명령"으로 오인**하는 것. 모달리티와 에이전트 자율성이 늘수록 이 오인이 일어날 표면만 넓어진다.

## 1. 멀티모달 공격 — 안전 정렬이 시각·음성으로 전이되지 않는다

- **시각 적대적 예제(정본)**: Qi et al. *"Visual Adversarial Examples Jailbreak Aligned LLMs"*(arXiv 2306.13213, AAAI 2024). 핵심: 이미지는 **연속·고차원**이라 텍스트로 학습된 안전 정렬이 시각 임베딩으로 전이되지 않고, **단일 범용 적대 이미지 하나**로 다양한 유해 지시를 우회.
- **타이포그래피 인젝션**: Gong et al. *"FigStep"*(arXiv 2311.05608, AAAI 2025 Oral). 금지 텍스트를 **이미지 속 글자로 렌더링**해 텍스트 필터를 우회 → 양성 텍스트 프롬프트로 유해 출력 유도. (저자 주장 6개 LVLM 평균 ASR ~82.5%)
- **오디오 계보**: 은닉 음성명령(Practical Hidden Voice Attacks, arXiv 1904.05734) → 음성 파운데이션모델 범용 음향공격(Muting Whisper, 2405.06134) → Audio-LLM 대상 적대. 공통 개념: 사람에겐 정상으로 들리는 반송(carrier) 오디오에 기계만 인식하는 명령 은닉.

> **방어자 함의**: 텍스트 입력 필터·안전 정렬만으로는 부족. 멀티모달 시스템은 **각 모달리티마다 별도 공격면**을 가지며, 특히 이미지 채널은 필터링이 어렵다. [매뉴얼](/ko/posts/kisa-ai-threat-response-manual/)의 모델(M) 위협을 멀티모달로 확장해 볼 관점.

## 2. 간접 프롬프트 인젝션(IPI) — 원격 조종의 정본

- **정본**: Greshake et al. *"Not what you've signed up for"*(arXiv 2302.12173, ACM AISec '23). 공격자가 직접 인터페이스 없이 **LLM이 나중에 검색·참조할 콘텐츠(웹페이지·문서·이메일)에 프롬프트를 심어** 원격으로 앱을 조종하는 벡터를 정식화.
- 제시 위협: 추론시점 원격제어, **지속 침해(persistent compromise)**, 데이터 탈취, **문서 간 전파(worming)**, DoS. 당시 Bing Chat·코드 자동완성 등에 PoC 시연(저자 주장).
- **근본 원인**: 직접 인젝션과 달리 **신뢰되지 않은 외부 콘텐츠를 데이터가 아닌 명령으로 오인** — 이 글 전체를 관통하는 단일 결함.

## 3. 에이전트/툴사용 레드티밍 — 자율성이 표면을 넓힌다

- **툴사용 에이전트의 IPI 취약성**: InjecAgent 기준 ReAct 프롬프트 GPT-4가 약 **24%** 사례에서 공격에 취약(§6).
- **컴퓨터사용·브라우저 에이전트 하이재킹**: 스크린샷/온스크린 콘텐츠에 심긴 프롬프트가 **시각 채널로 에이전트를 조종**하는 visual prompt injection이 신규 표면(VPI-Bench 2506.02456, 세부 미검증).
  - **벤더 대응(주장)**: Anthropic은 브라우저 사용 시 화면 내용에 인젝션이 있을 수 있음을 명시하고 탐지 분류기를 추가했으나 "위험이 완전히 해결되지는 않았다"고 밝힘(자체 발표).
- **코딩 에이전트**: Cursor·Claude Code·Copilot 등 실제 코딩 에이전트 대상 **툴 호출 하이재킹** 실증 연구 보고(arXiv 2509.05755, 초록 수준 확인).

## 4. MCP(Model Context Protocol) 보안 — 도구 설명이라는 새 공격면

- **툴 포이즈닝(Tool Poisoning Attack)**: 2025-04 Invariant Labs 최초 공개. **도구 설명(description) 필드 — LLM엔 보이나 사용자엔 잘 안 보이는 메타데이터 — 에 악성 지시를 은닉**하는 IPI의 특화형. (다수 2차 보도로 교차확인)
- 알려진 MCP 위험(개념): 도구설명 인젝션 · **rug-pull**(설치 후 도구정의 몰래 교체) · 서버 간 교차오염(shadowing) · 과도권한(over-privilege).
- **대응**: Invariant Labs의 정적분석 도구 **MCP-Scan**(설치 전 메타데이터 검사·신뢰도구 pinning·allowlist). 학술 정리로 *"Systematic Analysis of MCP Security"*(arXiv 2508.12538).

> **SIEM/에이전트 운영 함의**: MCP 도구 설명·rug-pull은 **소프트웨어 공급망 공격의 AI 판(版)** — 신뢰 경계가 "코드 패키지"에서 "도구 메타데이터"로 이동. 도구 정의 변경 감시·설치 전 스캔·최소권한이 그대로 필요.

## 5. 표준 프레임워크 매핑 — OWASP·KISA

**OWASP LLM Top 10 (2025)** — 관련 항목:
- **LLM01 Prompt Injection**(2회 연속 1위): §1~4의 직접·간접·시각·툴 인젝션이 모두 여기 매핑.
- **LLM06 Excessive Agency**: 에이전트 특화. 근본원인을 **Functionality(과다 도구)·Permissions(과다 권한)·Autonomy(감독 없는 자율성)** 로 정의 → §3·§4의 에이전트 위험과 직결.
- 단, OWASP Top 10 2025 본편에 "agentic" 독립 항목은 없고, 별도 트랙 **OWASP Agentic Security Initiative**의 *"Agentic AI — Threats and Mitigations"*(2025-02)·*"Top 10 Risks & Mitigations for Agentic AI"*(2025-12)가 에이전트 위협을 Agent Design·Memory·Planning·Tool Use·Deployment 축으로 다룸.

**KISA 위협코드(에이전트 A계열)**: 매뉴얼이 **에이전트 하이재킹**(외부 문서·웹의 은닉 악성 프롬프트를 정상 명령으로 오인)을 신규 공격유형으로 명시 — §2 Greshake IPI가 정확히 이것. 단, **구체 코드 라벨 A01~A04의 정의는 KISA 원문 PDF 대조 필요**(공개 웹 미확인, 추측 배제).

## 6. 벤치마크 — 에이전트 IPI를 어떻게 측정하나

| 벤치마크 | 출처 | 무엇을 측정 |
|---|---|---|
| **InjecAgent** | arXiv 2403.02691 | 툴통합 에이전트의 **IPI 취약성**. 1,054 케이스, 사용자도구 17·공격자도구 62종, 단일턴. 직접 유해행위 유도 / 데이터탈취형 유도 2축. ReAct GPT-4 ~24% 취약 |
| **AgentDojo** | arXiv 2406.13352, NeurIPS 2024 | **신뢰불가 데이터 위 도구실행** 에이전트를 동적 평가. 도구 70·과제 97·인젝션목표 27. 인젝션 상황에서 (a)원과제 수행 utility (b)공격 함락 security를 **end-to-end 다단계**로 동시 측정 |

> **차이**: InjecAgent은 고립된 단일 스텝, AgentDojo는 도구선택·과제완수까지 포함한 현실적 실행을 모사. 방어 평가엔 **utility와 security를 함께** 보는 AgentDojo식이 실전적 — "공격을 막느라 정상 기능까지 죽이면 실패"라는 균형을 강제.

## 종합 — 확장 표면의 단일 원리 (방어자 관점)

1. 모달리티·자율성이 늘어도 **근본 결함은 하나**: 신뢰불가 입력(픽셀·외부문서·도구설명)을 명령으로 오인. §1 이미지, §2 외부문서, §4 도구 메타데이터는 같은 병의 다른 증상.
2. **에이전트는 위험을 증폭**한다 — 툴 실행 권한 × 외부 콘텐츠 접촉 × 자율성이 곱해져, 인젝션이 "유해 텍스트 출력"을 넘어 **실제 행동(데이터 유출·도구 오남용)**으로 실현. OWASP LLM06(Excessive Agency)가 이를 짚음.
3. **MCP 시대의 공급망**: 신뢰 경계가 코드에서 도구 메타데이터로 이동. 설치 전 스캔·pinning·최소권한이 필수 — 전통 SW 공급망 방어의 AI 판.
4. **측정 성숙**: InjecAgent·AgentDojo로 에이전트 IPI 취약성을 정량화 가능. 방어 검증엔 security만이 아니라 **utility 동시 측정**(AgentDojo식)이 실전 기준.
5. **SIEM/SOC 접점**: 에이전트가 만드는 텔레메트리(예상외 도구 호출 시퀀스·외부 콘텐츠 참조 직후의 권한 상승 행동)를 탐지 대상으로. MCP 도구정의 변경·rug-pull은 공급망 무결성 모니터링 항목.

> **연결**: 이 확장 표면은 세 축 중 ①(AI가 표적)의 심화이자, 자율 에이전트가 곧 ②([AI가 도구](/ko/posts/ai-augmented-red-teaming/))의 실행 기반이기도 하다 — 즉 **공격당하는 에이전트와 공격하는 에이전트는 같은 기술의 양면**이다.
