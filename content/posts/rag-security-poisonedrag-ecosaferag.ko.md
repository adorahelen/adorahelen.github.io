## 논문 1: PoisonedRAG — RAG 지식 오염 공격

> **학회**: USENIX Security 2025 (보안 최고 학회)
> **저자**: Wei Zou 외 3인 (Penn State, Illinois Tech)
> **핵심**: RAG의 지식 데이터베이스에 악성 텍스트 5개만 주입하면, LLM이 공격자가 원하는 답변을 90%+ 확률로 생성한다.

### 공격 원리

RAG 시스템의 3요소(지식 DB, Retriever, LLM) 중 **지식 DB가 새로운 공격 표면**이다.

```
공격자:
  1. 타겟 질문 선택: "Who is the CEO of OpenAI?"
  2. 타겟 답변 선택: "Tim Cook" (거짓)
  3. 악성 텍스트 생성 → 지식 DB에 주입

악성 텍스트 = S ⊕ I
  S: 질문과 유사하게 만들어 검색되게 함 (Retrieval Condition)
  I: LLM이 타겟 답변을 생성하게 유도 (Generation Condition)
```

### 두 가지 핵심 조건

| 조건 | 설명 | 달성 방법 |
|------|------|---------|
| **Retrieval Condition** | 악성 텍스트가 타겟 질문에 대해 검색되어야 함 | Black-box: S = 타겟 질문 자체를 앞에 붙임 / White-box: HotFlip으로 임베딩 유사도 최적화 |
| **Generation Condition** | 검색된 악성 텍스트가 LLM을 속여 타겟 답변 생성 | GPT-4로 "이 질문에 이 답변이 나오는 문서"를 생성 (평균 2~3회 시도) |

### 공격 성능

| 데이터셋 | DB 크기 | Black-box ASR | White-box ASR | 주입 텍스트 수 |
|---------|--------|-------------|-------------|-----------|
| NQ | 2,681,468 | **97%** | **97%** | 5개 |
| HotpotQA | 5,233,329 | **99%** | **94%** | 5개 |
| MS-MARCO | 8,841,823 | **91%** | **90%** | 5개 |

- 8개 LLM(GPT-4, PaLM 2, LLaMA-2, Vicuna 등)에서 일관적으로 높은 ASR
- 고급 RAG(Self-RAG, CRAG)에서도 70~87% ASR 달성
- Wikipedia 기반 ChatBot(21M 텍스트)에서도 94~100% ASR

### 기존 방어의 한계

| 방어 방법 | ASR 감소폭 | 한계 |
|--------|---------|-----|
| Paraphrasing | 97%→87% | 여전히 높은 ASR |
| Perplexity 탐지 | AUC 0.30 | GPT-4가 생성한 텍스트라 품질이 높아 탐지 불가 |
| 중복 필터링 | 변화 없음 | 각 악성 텍스트가 다르게 생성됨 |
| Knowledge Expansion (k 증가) | 97%→41% (k=50) | 비용 급증, 완전 방어 불가 |

### 왜 위험한가

- 공격 비용 극히 낮음: GPT-4에 2~3번 쿼리 + 1초 미만
- Black-box 설정: Retriever/LLM 접근 불필요
- Wikipedia 편집, 가짜 뉴스 게시, 웹사이트 호스팅으로 주입 가능
- 비타겟 질문에 대한 영향: 0~0.4%로 미미 (탐지 어려움)

## 논문 2: EcoSafeRAG — RAG 방어 프레임워크

> **출처**: arXiv:2505.13506 (2025.05)
> **저자**: Ruobing Yao 외 4인 (중국과학원 정보공학연구소)
> **핵심**: 문장 수준 분할 + 미끼 기반 컨텍스트 다양성 검사로, LLM 내부 지식에 의존하지 않고 악성 콘텐츠를 탐지한다.

### 기존 방어의 문제점

| 기존 방어 | 문제 |
|--------|------|
| RobustRAG | 악성 문서 2개 이상이면 성능 저하 |
| TrustRAG Stage2 | LLM 내부 지식에 의존 → RAG 설계 철학과 모순 |
| InstructRAG | 토큰 소비 7.7배, 파인튜닝 필요 |

### EcoSafeRAG 아키텍처 (3단계)

```
사용자 질문 → [1. 문장 분할] → [2. 핵심 문장 선별] → [3. 미끼 기반 다양성 검사] → 정제된 입력 → LLM
```

#### Stage 1: 문장 수준 분할 (Sentence-level Segmentation)

- 검색된 문서를 NLTK로 문장 단위 분할
- 공격 구조를 해체 (대부분의 공격이 문서 수준에서 최적화되므로)
- 정상 콘텐츠의 중복 감소 + 핵심 문장 노출 강화
- **이것만으로도** Vanilla RAG 대비 정확도 26% 향상, 토큰 80% 절감

#### Stage 2: 핵심 문장 선별 (Core Sentence Screening)

이중 임계값 방식:

```
θ = τ × max(sim)    ← 적응형 임계값 (상대적)
τ_abs = 0.92         ← 절대 임계값

후보 문장 A = {s | sim(s, Q) ≥ θ}
의심 문장 Ip = {s | sim(s, Q) ≥ τ_abs}  ← 질문과 너무 유사하면 의심
```

- 정상 데이터의 99.97%는 τ_abs(0.92) 미만 → 오탐 거의 없음
- PoisonedRAG의 `S = Q ⊕ I` 구조는 높은 유사도를 보이므로 탐지됨

#### Stage 3: 미끼 기반 컨텍스트 다양성 검사 (Bait-guided Diversity Check)

핵심 통찰:
- **정상 문서**: 컨텍스트가 다양함 (여러 출처, 다른 표현)
- **악성 문서**: LLM 템플릿으로 생성되어 컨텍스트가 유사함

```
1. 후보 문장의 컨텍스트(같은 문서의 다른 문장들) 임베딩
2. 미끼 샘플 추가 (4종류 × 4개 = 16개)
   - 감정 조작, 강제 선택, 역할극, 프롬프트 인젝션
3. DBSCAN 클러스터링 (ε=0.6, min_samples=4)
4. 미끼와 같은 클러스터에 속하면 → 악성으로 판정
```

Cold Start 문제 해결:
- 악성 문서가 1개뿐이면 기존 클러스터링은 노이즈로 분류
- 미끼가 악성 문서 주변 밀도를 높여 클러스터 형성 유도
- N=1일 때 ASR: 35% → **0%**로 감소

### 실험 결과

#### 5개 악성 문서 주입 시 (주요 결과)

| 모델 | 방어 | 토큰 | GCG ACC | PIA ACC/ASR | Poison ACC/ASR | Clean ACC |
|------|------|------|---------|-------------|---------------|-----------|
| **Vicuna** | Vanilla RAG | 1315 | 24 | 2/57 | 14/72 | 39 |
| | TrustRAG S1 | 1078 | 29 | 40/3 | 47/2 | 40 |
| | **EcoSafeRAG** | **266↓80%** | **63** | **62/3** | **63/0** | **63↑23%** |
| **Llama2** | Vanilla RAG | 1315 | 17 | 14/82 | 23/70 | 51 |
| | TrustRAG S1 | 1078 | 29 | 54/3 | 48/3 | 54 |
| | **EcoSafeRAG** | **266↓80%** | **63** | **63/1** | **63/1** | **63↑14%** |
| **Llama3** | Vanilla RAG | 1315 | 6 | 28/67 | 13/77 | 57 |
| | InstructRAG ICL | 2320↑77% | 15 | 73/23 | 49/47 | 74↑17% |
| | **EcoSafeRAG** | **452↓66%** | **64** | **64/0** | **63/0** | **64↑7%** |

#### 핵심 수치

| 지표 | EcoSafeRAG |
|------|-----------|
| 최대 ASR | **3%** (전 모델/공격 평균) |
| Clean 정확도 향상 | Vicuna +23%, Llama2 +14%, Llama3 +7% |
| 토큰 절감 | 48~80% (Vanilla RAG 대비) |
| 레이턴시 | 1.2× Vanilla RAG |
| 클러스터링 시간 | 0.29초 |

### 각 방어 모듈의 기여 (Ablation, Vicuna 기준)

| 단계 | Clean ACC | PIA ASR (N=1) | PIA ASR (N=5) | Poison ASR (N=5) |
|------|-----------|-------------|-------------|---------------|
| Stage 1 (문장 분할만) | 65 (+26) | 35 | 73 | 0 |
| Stage 2 (+다양성 검사) | 59 | 2 | 2 | 0 |
| Stage 3 (+미끼 가이드) | 63 | **0** | **0** | **0** |

## 두 논문의 관계: 공격과 방어의 군비 경쟁

```
PoisonedRAG (공격)                    EcoSafeRAG (방어)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
Q ⊕ Md 구조로 검색 유도      →    문장 분할로 Q와 Md 분리, 높은 유사도 탐지
LLM 템플릿으로 Md 생성       →    컨텍스트 다양성 검사로 템플릿 패턴 탐지
Black-box 공격 (접근 불필요)  →    LLM 내부 지식 미사용 (RAG 원칙 준수)
5개 텍스트로 90%+ ASR        →    ASR을 0~3%로 감소
기존 방어 무력화              →    Plug-and-play, 추가 학습 불필요
```

### EcoSafeRAG가 PoisonedRAG를 막는 원리

1. **문장 분할**: `Q ⊕ Md`를 `Q`와 `Md의 문장들`로 분리 → 공격 구조 해체
2. **핵심 문장 선별**: `Q` 자체가 높은 유사도(>0.92)를 가지므로 의심 대상으로 표시
3. **다양성 검사**: Md의 문장들은 GPT-4 템플릿으로 생성되어 컨텍스트 패턴이 균일 → 비정상으로 분류
4. **미끼**: 악성 문서 1개만 있어도 미끼가 클러스터 형성을 도와 탐지

## 한계점 및 미해결 문제

### PoisonedRAG의 한계

- Close-ended 질문에 집중, Open-ended 질문 미검증
- 각 타겟 질문별 독립적 공격 (다중 질문 동시 최적화 미수행)
- 100% ASR 미달성 사례 존재

### EcoSafeRAG의 한계

| 한계 | 설명 |
|------|------|
| DBSCAN ε 값 | 데이터셋별 튜닝 필요 (현재 0.6 고정) |
| 미끼 설계 | 기존 공격 패턴 지식에 의존, 새로운 공격 유형에 대한 업데이트 필요 |
| 문장 분할 오버헤드 | 대규모 배포 시 전처리 비용 증가 (사전 인덱싱으로 완화 가능) |
| 적응형 공격 미검증 | 공격자가 EcoSafeRAG를 인지하고 우회 공격을 설계하면? |

### 열린 질문

- 공격자가 **다양한 컨텍스트를 가진 악성 문서**를 생성하면 다양성 검사 우회 가능?
- 문장 수준이 아닌 **단어/토큰 수준 공격**은?
- **멀티모달 RAG** (이미지 + 텍스트)에 대한 공격/방어는?

## 프로젝트 응용 가능성

### SIEM AI 분석 시스템

RAG 기반으로 보안 로그를 분석하는 시스템이라면, PoisonedRAG 유형 공격에 취약할 수 있다.

```
공격 시나리오:
  보안 지식 DB에 악성 텍스트 주입
  → "이 IP는 안전하다"라는 거짓 답변 유도
  → 실제 공격 트래픽을 정상으로 판단

방어 적용:
  EcoSafeRAG의 문장 분할 + 다양성 검사를
  RAG 파이프라인에 미들웨어로 삽입
```

구체적 적용:

| EcoSafeRAG 컴포넌트 | SIEM 시스템 적용 |
|-------------------|-------------------|
| 문장 분할 | 검색된 보안 문서를 문장 단위로 분할 후 재정렬 |
| 핵심 문장 선별 | 쿼리와 유사도 0.92 이상인 문장 의심 표시 |
| 다양성 검사 | KISA/MITRE 문서 컨텍스트의 다양성 확인 |
| 미끼 주입 | 알려진 공격 패턴 미끼로 클러스터링 가이드 |



## 종합 평가

| 항목 | PoisonedRAG | EcoSafeRAG |
|------|------------|-----------|
| **학회 수준** | USENIX Security (최고) | arXiv (미발표) |
| **기여도** | RAG 공격 표면 최초 정의 + 체계적 공격 설계 | 최초의 LLM 내부 지식 미의존 방어 |
| **실용성** | 공격 비용 극히 낮음, 즉시 실행 가능 | Plug-and-play, 파인튜닝 불필요 |
| **완성도** | 8 LLM × 3 DB × 다양한 설정 체계적 평가 | 3 공격 × 3 DB × 3 LLM 검증 |
| **한계** | 방어가 어렵다는 것만 보여주고 해결책 미제시 | 적응형 공격에 대한 검증 부족 |

### 핵심 인사이트

> **RAG 시스템은 외부 지식에 의존하는 만큼, 그 지식의 무결성이 보안의 핵심이다.** PoisonedRAG는 이 취약점을 5개 텍스트로 90%+ 공격 성공률을 달성하며 증명했고, EcoSafeRAG는 LLM 내부 지식에 의존하지 않으면서 문장 분할 + 컨텍스트 다양성 분석으로 ASR을 0~3%까지 낮출 수 있음을 보여주었다.

RAG를 운영하는 모든 서비스는 **지식 DB 오염 방어**를 반드시 고려해야 한다.
