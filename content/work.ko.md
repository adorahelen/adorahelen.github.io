일 밖에서 만든 네 개의 시스템입니다. 직업적으로 다루는 것과 같은 범주이고, 전부 "이게 어디서 깨지는지" 알고 싶어서 만들었습니다. 그래서 아래에는 기능만이 아니라 한계도 같이 적혀 있습니다.

이 중 둘은 공개돼 있습니다 — **[siem-trinity-public](https://github.com/adorahelen/siem-trinity-public)**(자작 XDR)과 **[ai-console-public](https://github.com/adorahelen/ai-console-public)**(온프레미스 에이전트 콘솔, MIT). 나머지는 비공개이고, 요청하시면 열람 권한을 드립니다.

## 자작 XDR

> 저장소: **[siem-trinity-public](https://github.com/adorahelen/siem-trinity-public)** · 공개

**수집 → 탐지 → 분석 → 대응, 한 호스트 위의 4계층 + SOC 콘솔.**

- 수집은 Zeek·Suricata·HIDS 에이전트로, 로그와 메트릭은 Loki와 Prometheus로.
- 탐지는 FastAPI 서비스. 병렬 탐지기 4종(isolation forest, 변동계수, 엔트로피, 룰 경로)이 단일 BFF 뒤의 엔드포인트 27개로 묶여 있습니다.
- 분석은 로컬 LLM에 ATT&CK 기법 697건을 벡터 저장소로 붙이고, 4섹션 고정 프롬프트(요약·공격체인·위험평가·권장대응)로 출력 형태가 흔들리지 않게 했습니다.
- **6단계 자동 대응 체인** — 호스트 가시성, 자동 IP 차단, active response, 위협 인텔 매칭, SOAR 플레이북, 케이스 생성.

**면접에서 물어볼 만한 판단**: 6단계 전부 구현했고 운영 토글 4개는 전부 **꺼진 채로** 나갑니다. 오탐에 자동 차단이 걸리면 제 서비스가 끊깁니다. 보수적 기본값은 미완성이 아니라 결정입니다.

컨테이너 10개가 돌고 외부 노출 포트는 정확히 하나, 나머지는 전부 localhost 바인딩입니다.

## Go로 다시 지은 SIEM

**상용 SIEM이 다루는 기능 축을 마이크로서비스로 다시 지었습니다.**

- 제품이 덮는 범위를 기능 항목 128개로 정리하고, 다시 만들 값어치가 있는지로 4등급 분류한 뒤 항목 단위 매핑표를 유지했습니다 — 구현하지 않은 항목은 그 사유까지 적었습니다. 범위 규율이 핵심입니다. 그게 없으면 의견 없는 복제품이 됩니다.
- **Go 서비스 11개**로 재설계: 수집 게이트웨이, 파서·정규화, 저장 writer, 검색, 탐지·상관, 알림, 워크플로 엔진, 연동 어댑터, 설정·인증, 포워더, 콘솔.
- **탐지 룰 DSL과 파서를 직접 설계**하고 단계별 테스트를 붙였습니다. 남이 만든 언어로 룰을 쓰는 쪽이 아니라, 언어를 만든 쪽입니다.
- 원본에 없던 것을 더했습니다: SOAR 워크플로 엔진, TAXII 2.1 + STIX 파싱 기반 CTI, JWT + LDAP/AD + TOTP MFA.

기능 항목 128개 중 103개 구현, E2E 테스트 22/22 통과.

**이 프로젝트에서 나온 또 하나** — 제 시험용 바이너리에서 무인증 수집 엔드포인트를 스스로 발견하고, 침해사고 대응 전 과정을 문서로 남겼습니다. 재현, 인증 로직 부재를 입증한 바이너리 문자열 분석, 평문으로 수집돼 있던 범위 산정, 서버 측 차단, 그리고 코드 레벨 수정까지. **내 시스템에서 내가 찾았다는 게 핵심입니다.**

## User-mode EDR 센서

**C++ 2,840줄로 던진 질문 하나 — Ring 3는 어디까지 갈 수 있는가.**

- 프로세스 생성·종료, 파일 변경, IPv4 TCP 연결, 자동실행 레지스트리 키를 관측합니다. 전부 커널이 콜백으로 할 일을 유저모드 우회로로 대신한 것입니다.
- 우회로마다 대가가 있고, README에 그 대가를 하나씩 적었습니다. 파일 이벤트엔 유발 PID가 없고, 네트워크 폴링은 샘플 사이에 붙었다 끊긴 연결을 놓칩니다.
- 규칙 14종과 부모-자식 프로세스 상관까지 동작하는 룰 엔진. 이벤트는 SQLite에 쌓이고 Electron 콘솔이 1초마다 증분을 가져갑니다.
- `$MFT`·레지스트리 하이브·`.evtx`·Prefetch를 매니페스트와 해시로 담는 포렌식 수집 모드는 별도.

**Sysmon 이벤트 기준 자체 채점: 5 커버 · 3 부분 · 6 미커버** — 모듈 로드, 인젝션, `lsass` 접근이 사각이고, 사각인 채로 공개했습니다. 저장소 전체는 C/C++ 298,925줄이지만 **그중 제 코드는 2,840줄**이고, 누가 묻기 전에 README가 먼저 그렇게 적고 있습니다.

## 온프레미스 LLM 에이전트 콘솔

> 저장소: **[ai-console-public](https://github.com/adorahelen/ai-console-public)** · 공개 · MIT

**엔진은 고정, 도메인은 카트리지.**

- 프롬프트·지식·모델 세 슬롯이 각각 교체 가능합니다. 전부 원본 프로덕션 시스템에 이미 있던 통로를 쓰기 때문에, 도메인을 바꾸는 데 코드 수정이 없습니다.
- `install.sh`가 VRAM과 RAM을 감지해 하드웨어 티어를 판정하고, 모델 프리셋을 고르고, 서비스로 등록합니다. 한 명령으로 끝까지.
- 검색은 BGE-M3 dense + ColBERT 2-way RRF. 거기까지 가려고 비교했던 변형들이 저장소에 그대로 남아 있습니다.
- 지식의 출처를 파일 단위로 추적합니다 — 보안 카트리지 3,955건 = 공개 코퍼스 1,575 + 자체 작성 1,930 + 모델 생성 301, 라이선스 실사 기록 포함.

제 코드베이스 중 가장 크고 테스트가 가장 많습니다. Python 70,424줄, 테스트 파일 55개.

**빼도 됐지만 적어둔 것**: PII 마스킹이 한쪽 핸들러 경로에서만 돌아서 API 티어는 아직 원문을 밖으로 보냅니다. 버그가 아니라 제품 정체성 문제라서 미해결 항목으로 적어놨습니다.

## 연구

**김강민**, 변현수, 조민정, 김역, 손기욱, 이창훈 (2025). *디지털 포렌식 관점에서의 Threads 사용자 행위 분석.* 한국정보보호학회 동계학술대회 논문집(CISC-W'25), 제35권 제2호. **KISTI 원장상.**

제1저자. 루팅된 안드로이드 기기에서 열람 게시물과 그 시점, DM 본문과 발신자·시각, 전송 대기 중이던 미전송 이미지, 인앱 검색 기록 전체를 복원했습니다.

선행연구 3편이 이 앱의 모바일 분석은 수확이 적다고 평가했는데, 그걸 뒤집은 발견은 이것입니다 — **메시지 본문이 BLOB 컬럼 안에 평문으로 들어 있고, 가장 최근 메시지는 본 DB가 아니라 WAL(선기록 로그)에 있습니다.** 본 DB만 보는 절차로는 영영 보이지 않습니다.
